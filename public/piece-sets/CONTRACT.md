# Piece-set contract

Piece artwork is **data**. Two kinds exist, both listed in `public/piece-sets/sets.json`,
and neither needs a TypeScript change:

- a **character library** (the "Hlavy" style): `public/piece-sets/animals/` with one
  folder per character and `animals.json`; the player picks their character, the
  opponent's (or random) and a colour (or random). See "Character library" below.
- a **pair set**: one folder with the twelve `w*`/`b*` files (the classic and the
  full-figure goats/frogs). See "Pair sets" below.

## Character library

```
public/piece-sets/animals/animals.json
public/piece-sets/animals/<id>/light/{K,Q,R,B,N,P}.png   the character as the WHITE pieces
public/piece-sets/animals/<id>/dark/{K,Q,R,B,N,P}.png    the character as the BLACK pieces
public/piece-sets/animals/<id>/pieces.css                generated, scoped rules (below)
```

`animals.json`:

```json
{ "board": { "light": "#dce6f0", "dark": "#8fa3bd" },
  "animals": [
    { "id": "had", "name": "hadi", "za": "hady", "sound": "Sss!", "hurt": "Sss…",
      "levels": ["Vajíčko", "Hádě", "Užovka", "Zmije", "Krajta", "Hadí král"] }
  ] }
```

- `board` — one palette for the whole library (every character must read on it; see the
  quality gate). A per-character `board` override is not implemented yet.
- `id` — folder name, `/^[a-z0-9-]+$/`. `name` nominative plural ("hadi"), `za` accusative
  after "Hraju za …" ("hady"), `sound` the king's noise in the review bubbles, `hurt` the
  noise when one of its pieces is taken. `levels` (optional) — six difficulty labels,
  weakest first; without it the ladder's own (frog) names are used.
- `pieces.css` is generated by `scripts/extract-animals.py` and scopes every rule by a
  class on `<html>`: `html.skm-white-had .cg-wrap piece.king.white { … light/K.png }` and
  `html.skm-black-had .cg-wrap piece.king.black { … dark/K.png }`. The app loads the
  stylesheets of the two characters in play and sets the two classes; because the
  selectors are more specific than chessground's, they win over the bundled classic
  pieces without touching them. A missing stylesheet leaves that side on the classic
  pieces (error logged); a missing or broken `animals.json` removes the "Hlavy" style
  from the selector and the next style is used.
- Adding a character = a new sheet in `assets/source/animals/<id>.png` (1774×887, white
  background, dark row on top, light row below, Czech labels under each bust), one entry
  in `SOURCES` of the script, one entry in `animals.json`, run the script, check the
  contact sheets. The player's own character is never drawn as a random opponent;
  choosing the same character on both sides deliberately is allowed.

## Pair sets

A pair set is one folder under `public/piece-sets/<id>/` plus one entry in `sets.json`.

## Manifest entry

```json
{
  "id": "farm-busts-inverse",
  "name": "Hlavy",
  "family": "hlavy",
  "whiteAnimal": "zabky",
  "pair": "kuzlata-zabky",
  "board": { "light": "#dce6f0", "dark": "#8fa3bd" }
}
```

- `id` — folder name; lowercase letters, digits and hyphens only.
- `name` — label of the set's *family* in the "Figurky" selector (the first entry of a
  family names it).
- `family` — drawing style; sets of one family differ only in which animal is white.
  Optional: an entry without it is a one-member family named after its `id`.
- `whiteAnimal` — `kuzlata` or `zabky`: which animal the **white** pieces are. Optional;
  absent means the set has no animals (classic). For pair families the character selects
  are disabled ("—"); the family's entry matching the stored animal and the colour is
  shown when one exists, else the first entry. `w*` is always the white side.
- `library` — instead of a folder: the entry `{ "id": "hlavy", "name": "Hlavy",
  "family": "hlavy", "library": "animals" }` points at the character library above.
- `pair` — documents which animal pairing the set belongs to (backlog B1). No code reads it.
- `board.light` / `board.dark` — the board colours. They are **part of the set**, not a user
  setting, because readability depends on the pieces' palette (cream goats vanish on a
  classic cream/brown board).
- `stylesheet` — normally absent, meaning `piece-sets/<id>/pieces.css`. The single exception
  is `"stylesheet": null`, used only by the built-in `cburnett` entry: selecting it removes
  the set stylesheet so the styling bundled into the app shows through. No other set should
  use it.

The **first entry's family** is the default for a first visit, with the character
`kuzlata`, a random opponent and a random colour. Preferences live in `localStorage`
(`skm.pieceFamily`, `skm.animal`, `skm.opponent` = `random` | id, `skm.color` = `random` |
`w` | `b`; the pre-5A `skm.pieceSetId` is migrated once); unknown stored values fall back
to the defaults with a `console.warn`, and a missing or broken `sets.json` falls back to
the built-in classic pieces. Random draws happen once per game (Nová hra). A broken set must
never produce an unplayable board — worst case the classic pieces appear and an error is
logged.

## Folder contents

```
public/piece-sets/<id>/
  pieces.css
  wK.* wQ.* wR.* wB.* wN.* wP.*
  bK.* bQ.* bR.* bB.* bN.* bP.*
```

- Filenames exactly `wK wQ wR wB wN wP bK bQ bR bB bN bP`, case-sensitive, one extension
  per set (`.png` for raster, `.svg` for vector).
- `pieces.css` is the only place that knows filenames and extensions. It contains twelve
  rules of the form

  ```css
  .cg-wrap piece.pawn.white { background-image: url(wP.png); }
  ```

  (roles `pawn knight bishop rook queen king`, colours `white black`). Image URLs are
  relative to the stylesheet. Chessground sizes the image with `background-size: cover`
  into a square box; a set may restate `background-size: contain; background-position:
  center; background-repeat: no-repeat;` on `.cg-wrap piece`, but must not rely on
  anything in `src/`.

## Artwork rules

- **Square canvas.** Raster: 256×256 PNG with alpha (the browser scales down; this keeps
  pieces sharp on high-DPI screens). Vector: square `viewBox`, `0 0 64 64`.
- **One scale factor for all twelve pieces** is the default: relative sizes must match
  real pieces (a pawn is smaller than a king; both kings are the same height). A documented
  per-role adjustment is permitted when the source art's proportions differ sharply from
  chess convention (for example a pawn under ~55 % of the king's height). It must be applied
  identically to both sides and preserve the ordering pawn < knight ≈ bishop < rook <
  queen < king. Record it in the extraction script.
- **Bottom-aligned on a shared baseline.** The tallest piece stands at roughly 90 % of the
  canvas height; every piece's bottom sits on the same line with a small margin (≈ 4–5 %)
  below so it does not touch the square edge.
- **Identifiable at 40 px.** Test by rendering at 40 px, not by looking at the full-size
  file. Outlines must stay visibly continuous at 40 px on both the light and the dark
  square colour of the set.
- **Sides distinguishable under `filter: grayscale(1)`.** In particular the two kings.
- **Transparent background, no white halo** around the outline, no opaque fringe or
  leftover background outside the silhouette.
- Horizontal centring follows the body/base, not the raw bounding box (a knight's head or
  a bishop's bow extending to one side must not shift the piece off its square).

## Quality gate

Before a set ships, render all twelve pieces in a row at 40 px on the set's light squares,
again on its dark squares, and once more in greyscale (`docs/piece-contact-sheet.png` for
`farm`, produced by `scripts/extract-pieces.py`). If a piece is not identifiable at 40 px,
or the two kings are hard to tell apart in greyscale, the set is not done.

## Provenance and attribution

- `cburnett` (built-in): chess pieces by Colin M.L. Burnett, licensed CC BY-SA 3.0, as
  bundled by `@lichess-org/chessground`.
- `farm`: AI-generated character sheets in `assets/source/goats.png` (white) and

  reproduces the files.

  frogs from `farm-busts.png` / `farm-busts-inverse.png`, every other character from its
  own white-background sheet), extracted by `scripts/extract-animals.py`, which prints
  every enclosed-pocket verdict (flat white = background) for review.
